# WEEKLYREPORT — Local Weekly Commodity Report Pipeline

A simple, local Python pipeline for generating professional weekly commodity
market reports. Historical reports are used as style and narrative references
only — they are never copied into the new report.

---

## Project Purpose

This pipeline automates the generation of HigbyBarrett weekly commodity market
reports by:

1. Converting historical PDF/DOCX reports into clean markdown text
2. Classifying them by report type (post_wasde, pre_wasde, weekly)
3. Selecting the most relevant historical reports as style references for the chosen mode
4. Combining the style guide, writing instructions, selected references, and current
   weekly data into a single prompt
5. Saving the prompt to `output/` for manual or automated LLM use

Everything runs locally. No cloud infrastructure required until you add an LLM.

## Folder Structure

```
WEEKLYREPORT/
├── reports_raw/          # Drop original PDF and DOCX files here
├── reports_clean/        # Converted markdown (auto-generated by convert_reports.py)
├── reports_final/        # Cleaned markdown used as style references
├── weekly_data/          # Weekly market data — one subfolder per report date
│   └── 2026-03-12/       # Example: data pack for the March 12 report
│       ├── market_prices.md   ← CME front-month closes, weekly change
│       ├── spreads.md         ← calendar spreads and % of full carry
│       ├── exports.md         ← USDA inspections and sales
│       ├── basis.md           ← cash basis by region and market type
│       ├── cftc.md            ← CFTC managed money positioning
│       ├── weather.md         ← crop progress and South American conditions
│       ├── wasde.md           ← WASDE numbers (post_wasde mode only)
│       └── notes.md           ← analyst observations and context
├── prompts/              # Style guide, instructions, selected references, built prompts
├── scripts/              # All pipeline scripts
├── output/               # Assembled prompts and generated report drafts
├── logs/                 # Log files from each script run
├── README.md             # This file
├── CLAUDE.md             # Persistent instructions for Claude Code
└── requirements.txt      # Python dependencies
```

## First-Time Setup

```bash
pip install -r requirements.txt
```

Process historical reports once (only needed when adding new history):

```bash
python scripts/convert_reports.py    # PDF/DOCX → markdown in reports_clean/
python scripts/clean_reports.py      # remove artifacts → reports_final/
python scripts/build_style_corpus.py # combine into prompts/style_corpus.md
```

## Weekly Workflow

### Step 1 — Create the weekly data pack

Make a subfolder named by the report date and add your market data files:

```bash
mkdir weekly_data/2026-03-12
```

Add files to that folder (see `weekly_data/README.md` for full content descriptions):

| File | Contents | Required for |
|---|---|---|
| `market_prices.md` | CME closes, weekly change | all modes |
| `spreads.md` | Calendar spreads, % of full carry | all modes |
| `exports.md` | USDA inspections and sales | all modes |
| `basis.md` | Cash basis by region and type | all modes |
| `cftc.md` | CFTC managed money positioning | all modes |
| `weather.md` | Crop progress, South America | all modes |
| `wasde.md` | WASDE key numbers | post_wasde only |
| `notes.md` | Analyst observations | optional |

### Step 2 — Run the pipeline

One command, depending on your report type:

**Post-WASDE** (WASDE was released this week):
```bash
python scripts/generate_report.py --mode post_wasde --date 2026-03-12
```

**Pre-WASDE** (WASDE is due next week):
```bash
python scripts/generate_report.py --mode pre_wasde --date 2026-03-12
```

**Weekly** (no major USDA report this week):
```bash
python scripts/generate_report.py --mode weekly --date 2026-03-12
```

### Step 3 — Use the prompt

The pipeline saves the fully assembled prompt to:

```
output/post_wasde_prompt.txt    (or pre_wasde_prompt.txt / weekly_prompt.txt)
```

**Option A — Paste it manually** into Claude, ChatGPT, or any other LLM.

**Option B — Connect an LLM** by implementing `call_llm()` in
`scripts/generate_report.py`. When connected, the report is saved to:
```
output/2026-03-12_post_wasde_report.md
```

## How Mode Selection Works

When you run `generate_report.py --mode <mode>`, the pipeline does this in order:

1. **Selects reference reports** matching the mode from `reports_final/`.
   - For `post_wasde`: selects the 3 most recent post-WASDE historical reports
   - For `pre_wasde`: selects the 3 most recent pre-WASDE historical reports
   - For `weekly`: selects the 3 most recent standard weekly reports
   - Selection uses a WASDE release calendar (see `scripts/select_reports.py`)

2. **Loads style files** from `prompts/style_guide.md` and
   `prompts/writing_instructions.txt`.

3. **Assembles the prompt** in this order:
   - Style guide (tone, structure, analytical conventions)
   - Writing instructions (standing do/don't rules)
   - Historical reference reports (mode-matched, with explicit anti-copying rules)
   - Weekly market data (your files from `weekly_data/<date>/`)
   - Task block (mode-specific structure and content requirements)

4. **Saves the prompt** to `output/<mode>_prompt.txt`.

The prompt explicitly forbids copying sentences, reusing opening lines,
reusing "So What?" wording, and mirroring any prior report's structure.
Freshness is enforced at the prompt level — the references teach the voice,
not the content.

## Report Modes

| Mode | When to use | Primary focus |
|---|---|---|
| `post_wasde` | The week WASDE was released | WASDE balance sheet changes, market reaction, cash adjustment |
| `pre_wasde` | The week before WASDE | Market setup, trade expectations, WASDE risk scenarios |
| `weekly` | All other weeks | Price drivers, basis, exports, funds positioning |

## Running Steps Individually

Each script can be run independently:

```bash
# Select references for a mode (writes prompts/selected_reports.txt)
python scripts/select_reports.py --mode post_wasde --n 3

# Build the prompt (reads selected_reports.txt + weekly data)
python scripts/build_prompt.py --mode post_wasde --date 2026-03-12 \
  --data-dir weekly_data/2026-03-12

# Inspect the built prompt before using it
cat prompts/prompt_2026-03-12_post_wasde.txt

# Run the full orchestration (select + build + save to output/)
python scripts/generate_report.py --mode post_wasde --date 2026-03-12
```

## Connecting an LLM

Open `scripts/generate_report.py` and replace the body of `call_llm()` with
one of the three commented-out examples in the `LLM INTEGRATION` block:

- **Ollama** (local, no API key needed) — recommended first step
- **Anthropic Claude API** — set `ANTHROPIC_API_KEY` in environment
- **OpenAI API** — set `OPENAI_API_KEY` in environment

Once connected, run `generate_report.py` as usual. The report draft is saved to:
```
output/<date>_<mode>_report.md
```

## What Each Script Does

| Script | Purpose |
|---|---|
| `convert_reports.py` | Converts PDF/DOCX in `reports_raw/` to markdown in `reports_clean/` |
| `clean_reports.py` | Removes PDF artifacts; saves cleaned files to `reports_final/` |
| `build_style_corpus.py` | Combines all cleaned reports into `prompts/style_corpus.md` |
| `select_reports.py` | Classifies reports by type; writes `prompts/selected_reports.txt` |
| `build_prompt.py` | Assembles style guide + instructions + references + data into one prompt |
| `generate_report.py` | Orchestrates the full pipeline; saves prompt or report to `output/` |
